1C#と.NETの全体像元資料 STEP1

まず、「C#」「.NET」「Visual Studio」という3つの言葉の関係を整理します。この3つは混同されやすいのですが、役割がまったく違います。

3つの登場人物:言語・実行基盤・道具

C#(シーシャープ)とは

C#は、Microsoftが開発したプログラミング言語です。オブジェクト指向(データと処理を「モノ」単位でまとめて整理する考え方。第11章で詳しく説明します)に対応しています。Windowsアプリ、Webアプリ、業務システム、クラウドのサービス、ゲーム(Unity)など、幅広い用途で使われています。

.NET(ドットネット)とは

.NETは、C#などで書いたプログラムを動かすためのプラットフォーム(土台となる環境)です。大きく2つの役割があります。

  • 実行する仕組み(ランタイム):書いたプログラムをコンピューター上で実際に動かします。
  • 部品の倉庫(クラスライブラリ):「ファイルを読む」「日付を計算する」「データベースにつなぐ」など、よく使う機能があらかじめ部品として用意されています。業務システムのコードは、この部品を組み合わせて作られています。

Visual Studioとは

Visual Studioは、Microsoftが提供する統合開発環境(IDE)です。IDEとは、コードを書く・動かす・間違いを探す(デバッグ)・調べる、といった作業を1つのソフトでできるようにした道具のことです。C#専用ではなく、Visual BasicやC++などの言語にも対応しています。VS Codeとの違いは第2章で説明します。

.NETの歴史 ─ 「どの.NETか」でコードの見た目が変わる最新化

.NETには長い歴史があり、名前が何度か変わっています。社内のシステムがどの世代の.NETで作られているかによって、コードの書き方が少しずつ違います。

そのシステムが「どの.NET」で作られているかの見分け方

プロジェクトのフォルダーにある .csproj という設定ファイルを開くと分かります。

新しい.NET(例:.NET 10) 
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
.NET Framework(例:4.8) 
<Project ToolsVersion="15.0" ...>
  <PropertyGroup>
    <TargetFrameworkVersion>v4.8</TargetFrameworkVersion>
    ...(非常に長い)...
  </PropertyGroup>

net10.0、net8.0 のような形なら新しい.NET、v4.8 のように「v」で始まるなら.NET Frameworkです。

このファイルから何が分かる?

ある社内システムのプロジェクトで、次の .csproj ファイルが見つかりました。

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>WinExe</OutputType>
    <TargetFramework>net8.0-windows</TargetFramework>
    <UseWindowsForms>true</UseWindowsForms>
  </PropertyGroup>
</Project>
答えと解説
  • 4行目 net8.0-windows:.NET 8で作られた、Windows専用のアプリです。
  • 5行目 UseWindowsForms:画面はWindowsフォーム(第15章)で作られています。
  • 3行目 WinExe:画面を持つWindowsアプリ(実行ファイル)です。

さらに、.NET 8は2026年11月10日にサポートが終わるので、「.NET 10への移行計画はあるか」を開発ベンダーに確認すべきだ、ということも読み取れます。コードが読めると、こうしたシステム管理上の判断にも役立ちます。

  • .NETには .NET Framework(古い・Windows専用)と .NET(5以降・現在の主流)があります。
  • 2026年9月時点の最新は .NET 10(LTS)と C# 14 です。

ソリューションとプロジェクト

C#のプログラムは、たくさんのファイルでできています。それらを整理する単位がプロジェクトとソリューションです。

  • プロジェクト:1つのアプリ(または部品)を作るためのファイルをまとめた単位。設定ファイルは .csproj。
  • ソリューション:関係する複数のプロジェクトをまとめた単位。設定ファイルは .sln(新しい形式では .slnx)。

ソリューションを開くと、含まれているプロジェクトもまとめて開きます。この構成は、Visual Studioではソリューションエクスプローラー、VS Code(C# Dev Kit)でもソリューションエクスプローラーというツリー表示で確認できます。

デバッグ機能 ─ コードを「読む」ための最強の道具

最初のHello World

まずは1行のプログラム:Hello World🆕 追加

プログラミングの最初の一歩は、画面に「Hello, World!」と表示するプログラムです。現在のC#では、たった1行で書けます。

コード例 3-1 画面に文字を表示する(新しい書き方)Program.cs
Console.WriteLine("Hello, World!");
実行結果
Hello, World!
行ごとの解説
  1. Console(コンソール=文字だけの黒い画面)の WriteLine(1行書き出す)という命令を使って、"Hello, World!" という文字を表示します。最後の ;(セミコロン)は「命令の終わり」の印です。

ところが、少し前のC#や既存のシステムでは、同じことを次のように書いていました。

コード例 3-2 画面に文字を表示する(従来の書き方)Program.cs
using System;

namespace HelloApp
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello, World!");
        }
    }
}
実行結果
Hello, World!
行ごとの解説
  1. System という部品のグループ(名前空間)を使う、という宣言です。これがあると System.Console を Console と短く書けます。
  2. HelloApp という名前空間(名前のグループ)を作ります。次の { から最後の } までがその中身です。
  3. Program というクラス(処理をまとめる入れ物)を作ります。
  4. Main というメソッド(処理のまとまり)を作ります。Main はプログラムの入口で、実行するとここから始まります。
  5. 画面に文字を表示します。実際に仕事をしているのはこの1行だけです。
  6. 閉じかっこ } で、メソッド・クラス・名前空間を順に閉じます。

コード例3-1は、コード例3-2の「外側の決まりきった部分」をC#が自動で補ってくれる書き方です。これをトップレベルステートメントといいます(C# 9、.NET 5 から。.NET 6 以降は新しいプロジェクトの標準)。既存の基幹システムの多くは3-2の書き方なので、両方の形を知っておきましょう。

プログラム全体の構造:入れ子の箱

コード例3-2のように、C#のプログラムは箱の中に箱が入った入れ子構造になっています。

用語意味見分け方
名前空間(namespace)クラスなどを分類するためのグループ名。同じ名前のクラスがあっても、名前空間が違えば区別できるnamespace ○○
クラス(class)データと処理をまとめた入れ物。C#のプログラムの基本単位class ○○
メソッド(method)ひとまとまりの処理。やりたいことはメソッドの中に書く名前( ) の後に { }
ステートメント(文)1つ1つの命令多くは ; で終わる
ブロック{ と } で囲んだひとかたまり{ … }
型(type)クラスをはじめとする、プログラムを構成する部品の総称。「データの種類」の意味でも使う(第4章)─
かっこ { } の対応を見失わない

入れ子が深くなると、どの } がどの { に対応しているか分からなくなります。コードは字下げ(インデント)をそろえて書かれているので、同じ字下げ位置の { と } がペアだと考えて読みましょう。Visual StudioやVS Codeでは、かっこの横をクリックすると対応するかっこが強調表示されます。

usingディレクティブと完全修飾名

.NETの部品は名前空間で分類されています。たとえば、画面に文字を表示する Console は System という名前空間にあります。ほかの名前空間の部品を使う方法は2つあります。

① 完全修飾名で書く(フルネーム) 
System.Console.WriteLine("こんにちは");
② using で名前空間を宣言しておく 
using System;
Console.WriteLine("こんにちは");
住所の書き方と同じです

社外に郵便を出すときは「東京都千代田区○○1-2-3 総務部 佐藤様」とフルネームで書きます(完全修飾名)。社内便なら「総務部 佐藤さん」で届きます。using は「この書類の中では、うちの会社の住所は省略します」と最初に宣言しておくようなものです。

「ファイルスコープ名前空間」と「global using」(C# 10 / .NET 6 以降)

新しいC#では、入れ子を浅くするための書き方が使えます。中身の意味は同じです。

従来:名前空間を { } で囲む 
namespace Company.Sales
{
    class Order
    {
    }
}
新:ファイルスコープ名前空間 
namespace Company.Sales;

class Order
{
}

namespace ○○; のように セミコロンで終わると、「このファイル全体がこの名前空間」という意味になり、字下げが1段浅くなります。

また、global using System; と書くと、プロジェクト内のすべてのファイルで using System; を書いたのと同じ扱いになります。新しいプロジェクトでは、よく使う名前空間(System など)が自動的に global using される設定(ImplicitUsings)が標準で有効です。そのため、ファイルの先頭に using がなくても Console などが使えます。

① 大文字と小文字を区別する

② 文の終わりにはセミコロン ;

4変数・定数・データ型元資料 STEP4

業務システムは、社員名・金額・数量・日付などのデータを次々に扱います。そのデータを一時的にしまっておく場所が変数です。コードを読むときは「この変数には何が入っているのか」を追いかけることが基本になります。

変数は「名札の付いた箱」

変数とは、データを一時的に入れておくための領域に名前を付けたものです。C#では、箱を用意するときに「どんな種類のデータを入れる箱か」(型)を必ず決めます。

コード例 4-1 社員データを変数に入れて表示する
string employeeName = "佐藤 花子";
int age = 34;
decimal salary = 280000m;
bool isManager = false;

Console.WriteLine(employeeName);
Console.WriteLine(age);
Console.WriteLine(salary);
Console.WriteLine(isManager);
実行結果
佐藤 花子
34
280000
False
行ごとの解説
  1. string(文字列)型の箱 employeeName を作り、"佐藤 花子" を入れます。文字列は " " で囲みます。
  2. int(整数)型の箱 age に 34 を入れます。
  3. decimal(10進数の小数)型の箱 salary に 280000 を入れます。末尾の m は「decimal の値です」という印です。
  4. bool(真偽値)型の箱 isManager に false(いいえ)を入れます。
  5. それぞれの中身を表示します。bool の値は False と先頭が大文字で表示される点に注意してください。

変数を作ることを宣言、値を入れることを代入といいます。宣言と代入は分けて書くこともできます。

int stock;        // 宣言:int型の箱 stock を用意する
stock = 100;      // 代入:箱に 100 を入れる
stock = stock - 30; // 右側を計算(100-30=70)してから、箱に入れ直す → stock は 70
「=」は「等しい」ではなく「入れる」

数学では stock = stock - 30 は成り立ちませんが、C#の = は「右側の結果を左側の箱に入れる」という意味です。右から左へ読みましょう。「等しいかどうか」を調べるときは == を使います(第5章)。

コードに直接書いた小数(例:2.5)は、通常 double として扱われます。そのため、ほかの型の箱に入れるときは末尾に印を付けます。

float rate = 2.5f;       // float には f を付ける(付けないとエラー)

金額は decimal

double は、たとえば 0.1 + 0.2 が 0.30000000000000004 になるような、ごくわずかな誤差が出ることがあります。1円の誤差も許されない会計や販売のシステムでは、金額に decimal を使うのが定番です。コードの中で金額が double になっていたら、端数処理に注意が必要なサインかもしれません。

このように、コードに直接書き込んだ具体的な値(100、"山田商事"、true など)をリテラルといいます。

定数とローカル変数

定数とは、一度決めたら変更できない値です。const を付けて宣言します。

コード例 4-2 消費税率を定数にする
const decimal TaxRate = 0.10m;
decimal price = 1000m;
decimal tax = price * TaxRate;
Console.WriteLine(tax);
// TaxRate = 0.08m;  ← 定数は変更できないのでエラーになる
実行結果
100.00
  1. 消費税率 10% を定数 TaxRate として決めます。
  2. 1000 × 0.10 を計算して tax に入れます。
  3. 100.00 と表示されます。decimal は計算に使った小数点以下の桁数を保つため、.00 が付きます。
  4. 定数に値を入れ直そうとするとビルドでエラーになります(ここではコメントにしてあります)。

メソッドの { } の中で宣言した変数をローカル変数といいます。ローカル変数は、宣言したブロック { } の中だけで使えます。ブロックの外からは見えません。

「マジックナンバー」を避けるための定数

コードの中に price * 0.10m のように数字が直接書かれていると、「0.10 が何を意味するのか」が分かりません。業務コードでは TaxRate、MaxOrderCount のように意味のある名前の定数にしてあることが多く、定数名が仕様を読み解くヒントになります。readonly(読み取り専用)という似た仕組みもあります。

var(型の省略)

var ─ 型を省略した書き方🆕 追加

業務コードでは、型名の代わりに var と書かれていることがよくあります。右側の値から型をC#が自動で判断してくれる書き方です。

型を明示する 
string name = "佐藤";
int count = 10;
decimal price = 500m;
var を使う(意味は左と同じ) 
var name = "佐藤";   // string
var count = 10;      // int

7条件分岐元資料 STEP5

「在庫が足りていれば出荷、足りなければ入荷待ち」のように、条件によって処理を変えることを条件分岐といいます。業務ルールの多くは条件分岐として書かれているので、ここが読めると「このシステムはどういうルールで動いているか」が分かるようになります。C#の条件分岐の構文(選択文)には、if文とswitch文があります。

if文 ─ 「もし〜なら」

コード例 7-1 合否を判定する
int score = 80;
if (score >= 60)
{
    Console.WriteLine("合格");
}
else
{
    Console.WriteLine("不合格");
}
実行結果
合格
  1. 「もし score が 60 以上なら」。( ) の中に条件を書きます。
  2. 条件が true のときに実行されるブロックです。
  3. else は「そうでなければ」。条件が false のときに実行されます。else は省略できます(その場合、false なら何もしません)。

else if ─ 3つ以上に分ける

コード例 7-2 年間売上から顧客ランクを決める
decimal annualSales = 3500000m;
string rank;

if (annualSales >= 5000000m)
{
    rank = "プラチナ";
}
else if (annualSales >= 1000000m)
{
    rank = "ゴールド";
}
else if (annualSales >= 100000m)
{
    rank = "シルバー";
}
else
{
    rank = "一般";
}
Console.WriteLine($"顧客ランク:{rank}");
実行結果
顧客ランク:ゴールド
  1. 350万は500万以上ではないので false。次の else if へ進みます。
  2. 350万は100万以上なので true。rank に「ゴールド」を入れます。
  3. すでに条件が成立したので、残りの else if と else は判定すらされません。
else if は「上から順に、最初の1つだけ」

350万は「10万以上」にも当てはまりますが、シルバーにはなりません。先に成立した条件が優先されるからです。条件の並び順は業務ルールそのものなので、コードを読むときは上から順番に確認しましょう。

{ } が省略された if に注意

if の後の処理が1行だけのとき、{ } を省略して書けます。

if (stock <= 0)
    Console.WriteLine("在庫切れ");
    Console.WriteLine("発注してください");  // ← 字下げされているが、if とは無関係に必ず実行される

{ } がない場合、if の対象は直後の1文だけです。字下げに惑わされないようにしましょう。

switch文 ─ 値によって多方向に分ける

1つの値が「1なら…、2なら…、3なら…」のように、いくつかの決まった値のどれかによって処理を分けるときは、switch文がよく使われます。

コード例 7-3 支払方法コードを名前に変換する
int paymentType = 2;

{
    case 1:
        Console.WriteLine("現金");
        break;
    case 2:
        Console.WriteLine("銀行振込");
        break;
    case 3:
    case 4:
        Console.WriteLine("クレジットカード");
        break;
    default:
        Console.WriteLine("不明な支払方法");
        break;
}
実行結果
銀行振込
  1. switch ( ) の中の値(ここでは paymentType = 2)を調べます。
  2. case 1: は「値が1のとき」。case の後ろはコロン : です。
  3. 値が2なので、ここが実行されます。break で switch文から抜けます。
  4. case を縦に並べると「3または4のとき」という意味になります。
  5. default: は「どの case にも当てはまらないとき」。else のような役割です。
C#の多分岐は switch。break は必須
  • Visual Basic の Select Case のような「select文」は、C#にはありません。C#の選択文は if文と switch文です。
  • C#では、処理を書いた case の最後に break(または return など)がないとビルドエラーになります。break は繰り返し(第8章)だけでなく switch文でも使うことを覚えておきましょう。
  • switch では文字列も扱えます(例:case "東京":)。
switch式(C# 8 以降)

新しいコードでは、値を変換するだけの switch を、次のように短く書くことがあります。意味はコード例7-3とほぼ同じです。

コード例 7-4 switch式で書き直す

{
    1 => "現金",
    2 => "銀行振込",
    3 or 4 => "クレジットカード",
    _ => "不明な支払方法"
};
Console.WriteLine(paymentName);
実行結果
クレジットカード
  1. 「paymentType の値によって、次のどれかを paymentName に入れる」。switch が変数の後ろに来ます。
  2. 値 => 結果 は「この値なら、この結果」と読みます。or で複数の値をまとめられます。
  3. _(アンダースコア)は「それ以外すべて」。switch文の default にあたります。

三項演算子 ─ 1行で書く if〜else

条件 ? A : B は「条件が true なら A、false なら B」という意味です。簡単な分岐を1行で書くときに使われます。

ガード節 ─ 「ダメなら先に帰る」

業務コードのメソッドの先頭では、次のような if がよく並んでいます。

この章のまとめ
  • if (条件) { … } else { … } は「もし〜なら…、そうでなければ…」。else は省略できる。
  • else if は上から順に判定し、最初に成立した1つだけを実行する。

10メソッド元資料 STEP7 + 追加

メソッドは、ひとまとまりの処理に名前を付けたものです。業務システムのコードは、RegisterOrder(受注を登録する)、CalcTax(税を計算する)のようなメソッドの組み合わせでできています。メソッド名と「何を渡して、何が返ってくるか」が分かれば、中身を細かく読まなくても処理の流れがつかめます。

引数と戻り値

メソッドは自動販売機🆕 追加

  • 引数:メソッドに渡す値。「何について処理するか」の材料です。
  • 戻り値:メソッドが処理した結果として返す値。return で返します。
  • 何も返さないメソッドは、戻り値の型に void(空っぽ)と書きます。

メソッドの定義の読み方🆕 追加

コード例 10-1 消費税を計算するメソッドを呼び出す

PriceCalculator.PrintLine("消費税", tax);

class PriceCalculator
{
    public static decimal CalcTax(decimal price, decimal rate)
    {
        decimal result = price * rate;
        return result;
    }

    public static void PrintLine(string label, decimal amount)
    {
        Console.WriteLine($"{label}:{amount:N0}円");
    }
}
実行結果

  1. 呼び出し:CalcTax に 1000 と 0.10 を渡します。返ってきた結果(100)が変数 tax に入ります。
  2. PrintLine に "消費税" と tax を渡して表示させます。
  3. CalcTax の定義。渡された 1000 は price に、0.10 は rate に、順番どおりに入ります。
  4. return で計算結果を呼び出し元に返します。return を実行した時点でメソッドは終わりです。
  5. void なので、このメソッドは何も返しません。表示するだけの仕事をします。
💡 実行される順番

コードは上から書かれていますが、4行目以降の class の中身は「定義(手順書)」にすぎず、呼び出されたときに初めて実行されます。実行は1行目 → 6〜10行目(CalcTax)→ 1行目に戻る → 2行目 → 12〜15行目(PrintLine)の順です。

呼び出しの流れを追う🆕 追加

まずはメソッド名だけを拾い読みする

長いメソッドも、中の呼び出しを拾うと「チェックして(Validate)→ 合計を計算して(CalcTotal)→ 保存する(Save)」のように、手順の目次として読めます。詳細が必要になったら、その名前にカーソルを置いて F12(定義へ移動)で中に入りましょう。

オーバーロード ─ 同じ名前で引数違い

オーバーロードとは、同じクラスの中に、同じ名前で引数の異なるメソッド(またはコンストラクター。第11章)を複数定義することです。

コード例 10-2 引数の数によって使い分ける

class Printer
{
    public static void Show(string name)
    {
        Console.WriteLine($"氏名:{name}");
    }

    public static void Show(string name, int age)
    {
        Console.WriteLine($"氏名:{name}({age}歳)");
    }
}
実行結果
氏名:森
氏名:森(30歳)
  1. 引数が1つなので、6行目の Show(string name) が呼ばれます。
  2. 引数が2つ(string と int)なので、11行目の Show(string name, int age) が呼ばれます。
  3. 名前は同じ Show でも、引数の数や型が違うので別のメソッドとして扱われます。
戻り値の型だけが違うオーバーロードはできない

「名前も引数も同じで、戻り値の型だけが違う」メソッドは定義できません。呼び出す側から見て区別がつかないからです。どのメソッドが呼ばれるかは、呼び出すときの引数で決まります。実はおなじみの Console.WriteLine も、int 用・string 用などがオーバーロードされています。

11クラスとオブジェクト元資料 STEP6

ここからは、C#の最も大切な考え方であるオブジェクト指向プログラミングに入ります。業務システムのコードは、Employee(社員)、Order(受注)、Customer(顧客)のようなクラスの集まりでできています。クラスが読めれば、システムが「何を」「どう」扱っているかが見えてきます。

クラスは設計図、オブジェクトは実物

用語意味たとえ
クラスオブジェクトの雛形・設計図。どんなデータと操作を持つかを定義する記入欄だけの伝票用紙
オブジェクト(インスタンス)クラスをもとに、具体的な値を持たせて作った実物。作ることを「インスタンス化」という記入済みの伝票1枚1枚
フィールドオブジェクトが持つデータ(属性値)を保持する変数伝票の記入欄
メソッドオブジェクトの操作(振る舞い)伝票に対して行う作業
コンストラクターオブジェクトを作ったときに自動的に1回だけ呼び出される特別なメソッド。初期値の設定などを行う用紙を出したときの初期記入
メンバークラスを構成する要素(フィールド、メソッド、コンストラクター、プロパティなど)の総称─

📌 コンストラクターの特徴(試験に出るポイント)
  • クラス名と同じ名前にする
  • 戻り値の型は指定しない(void も書かない)

new が何回あるか = オブジェクトがいくつあるか

オブジェクトが新しく作られるのは new したときだけです。var b = a; は「同じ社員に別のあだ名を付けた」だけです。メソッドに渡したオブジェクトがメソッドの中で変更されると、呼び出し元から見ても変わっている、という動きもこれで説明できます。

class StockItem
{
    private string productCode;
    private int quantity;

    public StockItem(string productCode, int quantity)
    {
        this.productCode = productCode;
        this.quantity = quantity;
    }

    public void Receive(int qty)
    {
        quantity += qty;
    }

    public void Ship(int qty)
    {
        if (qty > quantity)
        {
            Console.WriteLine($"在庫不足のため出荷できません(要求 {qty}、在庫 {quantity})");
            return;
        }
        quantity -= qty;
    }

    public string GetStatus()
    {
        return $"{productCode}:在庫 {quantity}";
    }
}

(1) このクラスは何を表している? (2) 実行結果は?

答えと解説

(1) 1つの商品の在庫を表すクラスです。データとして商品コードと在庫数を持ち、操作として入庫(Receive)、出庫(Ship)、状態の表示用文字列の取得(GetStatus)ができます。出庫では、在庫が足りなければメッセージを出して何もしない、という業務ルールが組み込まれています。

(2) 20 → 出庫5で15 → 入庫12で27 → 出庫30は在庫不足で失敗、となります。

在庫不足のため出荷できません(要求 30、在庫 27)
P-100:在庫 27

「データ(在庫数)」と「それを正しく変更するためのルール(出庫チェック)」が1つのクラスにまとまっている点が、オブジェクト指向の典型的な形です。

12クラスをもっと読む ─ プロパティ・static・アクセス修飾子元資料 STEP7 + 追加

実際の業務コードのクラスには、public、private、static、{ get; set; } といった単語がたくさん並んでいます。この章では、それらの意味を読み解けるようにします。

アクセス修飾子

アクセス修飾子 ─ 誰が使ってよいか🆕 追加

クラスやメンバーの先頭に付く public や private をアクセス修飾子といいます。「どこから使ってよいか(公開範囲)」を表します。社内文書の「社外秘」「部外秘」のようなものです。

修飾子使える範囲よく付いているもの
publicどこからでも外部に提供するクラス、メソッド、プロパティ
privateそのクラスの中だけフィールド、内部だけで使う補助メソッド
protectedそのクラスと、それを継承したクラス派生クラスに使わせたいメンバー
internal同じプロジェクト(アセンブリ)の中だけプロジェクト内部だけで使うクラス
(何も書かない)メンバーは private、クラスは internal と同じ扱い─
public を見れば「そのクラスの使い方」が分かる

クラスを読むときは、まず public のメンバーだけを拾い読みしましょう。それが「外から頼める仕事の一覧(窓口)」です。private のメソッドは、その仕事を実現するための内部の作業手順なので、必要になってから読めば十分です。

プロパティ ─ データの受付窓口

フィールドを private で隠したうえで、外部との値のやり取りを受付窓口のように仲介する仕組みがプロパティです。外から見るとフィールドを直接触っているように見えますが、内部では値のチェックや加工ができます。

    p.Stock = -5;

static ─ クラスそのものに属するもの

これまでのフィールドやメソッドは、オブジェクト1つ1つが持つものでした(インスタンスメンバー)。これに対し、static が付いたものはクラスそのものに属し、全オブジェクトで共有されます。オブジェクトを作らなくても、クラス名.メンバー名で使えます。

コード例 12-2 static メソッドと static フィールド

var o2 = new Order();
var o3 = new Order();
Console.WriteLine($"作成された受注:{Order.Count}件");
Console.WriteLine($"o3の番号:{o3.No}");

class Calculator
{
    public static int Add(int a, int b)
    {
        return a + b;
    }
}

class Order
{
    public static int Count = 0;
    public int No;

    public Order()
    {
        Count++;
        No = Count;
    }
}

static メソッドの中からインスタンスメンバーは直接使えない

static メソッドは特定のオブジェクトに属していないので、その中から this や普通のフィールドを直接使うことはできません。「static = 共有・誰のものでもない」と覚えておきましょう。

この章のまとめ

  • static はクラスに属し、全オブジェクトで共有。オブジェクトを作らずに クラス名.メンバー名 で使う。

13継承とインターフェース元資料 STEP7 + 追加

業務システムでは、「正社員とパートは給与の計算方法が違うが、社員としての共通部分は同じ」のように、共通点と違いがあるものを扱う場面がたくさんあります。それを整理する仕組みが継承とインターフェースです。

継承 ─ 既存のクラスを引き継いで、差分だけ書く

継承とは、既存のクラス(基本クラス・親クラス)の機能を引き継いで、新しいクラス(派生クラス・子クラス)を定義することです。派生クラスには、基本クラスとの差分(追加・変更したい部分)だけを書きます。

「〜は〜の一種である」

継承は「正社員は社員の一種である」「管理職は正社員の一種である」という関係を表します。コードの class FullTimeEmployee : Employee は、「FullTimeEmployee は Employee の一種」と読みましょう。

オーバーライドと virtual / override / base

基本クラスのメソッドを派生クラスで作り直し、機能を置き換えることをオーバーライドといいます。基本クラス側で virtual(作り直してもよい)、派生クラス側で override(作り直した)を指定します。

コード例 13-1 もっとも簡単な継承とオーバーライド
Animal a = new Animal();
Dog d = new Dog();
a.Speak();
d.Speak();

class Animal
{
    public virtual void Speak()
    {
        Console.WriteLine("動物が鳴きます");
    }
}

class Dog : Animal
{
    public override void Speak()
    {
        Console.WriteLine("ワン");
    }
}
実行結果
動物が鳴きます
ワン
  1. virtual:「派生クラスで作り直してもよい」という許可です。
  2. class Dog : Animal:Dog は Animal を継承します。C#では継承をコロン : で表します。
  3. override:Animal の Speak を作り直します。Dog の Speak は「ワン」になります。
コード例 13-2 雇用形態ごとに月給を計算する
var staff = new List<Employee>
{

インターフェース ─ 「できること」の約束🆕 追加

インターフェースは、「このメソッドを必ず持っていること」という約束(契約)だけを定めたものです。中身(どう実現するか)は書きません。インターフェースの約束を守ってクラスを作ることを「インターフェースを実装する」といいます。

コード例 13-3 出力形式を差し替える

exporter.Export("受注一覧");

exporter = new PdfExporter();
exporter.Export("受注一覧");

{
    void Export(string title);
}

class CsvExporter : IExporter
{
    public void Export(string title)
    {
        Console.WriteLine($"{title} をCSVファイルに出力しました");
    }
}

class PdfExporter : IExporter
{
    public void Export(string title)
    {
        Console.WriteLine($"{title} をPDFファイルに出力しました");
    }
}

  2. 中身を PdfExporter に差し替えても、呼び出す側のコード(Export)は同じです。
  3. インターフェースの定義。メソッドの名前と引数だけで、中身はありません。名前は I で始めるのが慣習です。
  4. : IExporter:「IExporter の約束を守ります(実装します)」という宣言です。約束したメソッドがないとビルドエラーになります。
業務コードで見るインターフェースと、読むときの注意
  • IOrderRepository、IEmailSender、ILogger のように、I で始まる名前はインターフェースです。コンストラクターの引数に並んでいることが多く(依存性の注入。第16章)、「本番用はデータベースに保存、テスト用はメモリに保存」のように中身を差し替えられるようにしています。
  • List<T> が実装している IEnumerable<T>(1件ずつ取り出せる)、IDisposable(後片付けが必要。第14章)など、.NET自身もインターフェースを多用しています。
  • 読むときの落とし穴:インターフェースのメソッド上で F12(定義へ移動)を押すと、中身のない約束の部分に飛びます。実際の処理を見たいときは「実装へ移動」(Visual Studio / VS Code とも Ctrl+F12)を使いましょう。

この割引の仕組みを説明してください

DiscountPolicy policy = new MemberDiscount();
Console.WriteLine($"{policy.Apply(10000m):N0}");

policy = new CampaignDiscount(0.2m);
Console.WriteLine($"{policy.Apply(10000m):N0}");

abstract class DiscountPolicy
{
    public abstract decimal Apply(decimal price);
}

class MemberDiscount : DiscountPolicy
{
    public override decimal Apply(decimal price) => price * 0.95m;
}

class CampaignDiscount : DiscountPolicy
{
    private readonly decimal rate;

    public CampaignDiscount(decimal rate)
    {
        this.rate = rate;
    }

    public override decimal Apply(decimal price) => price * (1 - rate);
}
答えと解説
9,500
8,000
  • DiscountPolicy(割引方針)は抽象クラスで、「価格を受け取って割引後の価格を返す Apply」という枠だけを決めています。
  • MemberDiscount(会員割引)は 一律5%引き(×0.95)です。
  • CampaignDiscount(キャンペーン割引)は、作るときに渡した割引率(ここでは20%)で割り引きます。readonly は「コンストラクターで設定した後は変更しない」という意味です。

呼び出す側は policy.Apply(…) と書くだけで、どの割引方針を当てはめるかを差し替えられる設計になっています。新しい割引(例:誕生日割引)を追加するときも、クラスを1つ増やすだけで済みます。

  • オーバーライドは、基本クラスで virtual、派生クラスで override。
  • 基本クラスのメンバーは base で呼ぶ(super は使わない)。
  • インターフェースは「できること」の約束。名前は I で始まる。中身は差し替えられる。
  • インターフェースの実際の処理を見るには「実装へ移動」(Ctrl+F12)。

14例外処理元資料 STEP8

「ファイルが見つからない」「入力が数値ではない」「データベースにつながらない」─ 業務システムは、こうした想定外の事態に備えたコードを大量に含んでいます。業務コードの try〜catch を読めると、「どんなエラーを想定し、そのときどうするか」という設計が見えてきます。

例外とは

例外とは、プログラムの実行中に発生するエラー状態や、予期しない動作のことです。例外が発生すると、その内容を記録した例外クラスのオブジェクトが自動的に作られ、「投げられ(スローされ)」ます。何も対処しないと、プログラムはそこで強制終了してしまいます。

例外への対処をプログラムの中に書いておくことを例外処理といいます。

よく見る例外発生する状況
NullReferenceExceptionnull の変数の中身を使おうとした(第4章)
FormatExceptionint.Parse("abc") のように、形式が正しくない
OverflowException型に入りきらない値(byte.Parse("300") など)
DivideByZeroException整数を0で割った
IndexOutOfRangeException配列の範囲外の添字を使った(第9章)
ArgumentException とその仲間メソッドに不正な引数が渡された
FileNotFoundExceptionファイルが見つからない
InvalidOperationException今の状態ではその操作はできない

try-catch-finally の流れ

  2. 例外が発生したので、この行は実行されません。
  3. 発生した例外の型(OverflowException)に合う catch が実行されます。
  4. 型が合わないので、この catch は実行されません。
  5. finally は必ず実行されます。
catch は「具体的なものから順に」

catch は上から順に型が合うかどうか確認されます。catch (Exception ex) はすべての例外に合うので、最後に書くのが原則です。また、何でも受け止める Exception ではなく、独自の対処をしたい具体的な例外に対して catch を書くのが望ましいとされています。

using 文による後片付け

using 文 ─ 自動で後片付けする🆕 追加

ファイルやデータベース接続のように、使い終わったら必ず閉じる(解放する)必要があるものは、using 文で囲むのが定番です。ブロックを抜けると、例外が起きても自動的に後片付け(Dispose)されます。finally で閉じるのと同じ働きをします。

{
    string? line = reader.ReadLine();
    Console.WriteLine(line);
}   // ← ここで自動的にファイルが閉じられる
新(C# 8 以降):using 宣言 
using var reader = new StreamReader("orders.csv");
string? line = reader.ReadLine();
Console.WriteLine(line);
// ← メソッド(ブロック)の終わりで自動的に閉じられる
2つの using を混同しない

ファイル先頭の using System; は名前空間の省略宣言(第3章)で、メソッドの中の using (…) / using var … は後片付けの予約です。同じ単語ですが、まったく別の意味です。

この章のまとめ

ここまでの内容で、C#の文法の土台はそろいました。この章では、実際の基幹システムのコードで非常によく出てくる書き方を、「見たときに意味が分かる」ことを目標に紹介します。細部まで覚える必要はありません。実際のコードで出会ったときに戻ってくる辞書として使ってください。

ラムダ式 => ─ その場で書く小さなメソッド

業務コードには o => o.Amount >= 10000m のような書き方がたくさん出てきます。これはラムダ式といい、名前のない小さなメソッドをその場で書いたものです。

o や x などの1文字の名前がよく使われますが、「集まりの中の1件」を表していると考えれば読めます。

LINQ ─ データの集まりを絞り込む・並べる・集計する

LINQ(リンク)は、List や配列などのデータの集まりに対して、絞り込み・並べ替え・集計などを行う仕組みです。SQL の SELECT 文に似ています。業務コードで最もよく見る機能の1つです。

コード例 16-1 受注データを LINQ で分析する
var orders = new List<Order>
{
    new Order("A-001", "山田商事", 12000m, "東京"),
    new Order("A-002", "佐藤工業", 4500m, "大阪"),
    new Order("A-003", "山田商事", 30000m, "東京"),
    new Order("A-004", "田中物産", 8000m, "東京"),
};

var bigTokyoOrders = orders
    .Where(o => o.Region == "東京" && o.Amount >= 10000m)
    .OrderByDescending(o => o.Amount)
    .Select(o => o.OrderNo)
    .ToList();
Console.WriteLine(string.Join(", ", bigTokyoOrders));

Console.WriteLine(orders.Sum(o => o.Amount));
Console.WriteLine(orders.Count(o => o.Customer == "山田商事"));
Console.WriteLine(orders.Any(o => o.Amount > 50000m));
Console.WriteLine(orders.FirstOrDefault(o => o.Region == "福岡")?.OrderNo ?? "該当なし");

foreach (var g in orders.GroupBy(o => o.Customer))
{
    Console.WriteLine($"{g.Key}:{g.Sum(o => o.Amount):N0}円");
}

クエリ構文(SQL 風の書き方)

LINQ には、SQL によく似た書き方(クエリ構文)もあります。上の9〜13行目と同じ意味です。古めのコードで見かけることがあります。

var result = from o in orders
             where o.Region == "東京" && o.Amount >= 10000m
             orderby o.Amount descending
             select o.OrderNo;
First と FirstOrDefault の違いは重要

First() は該当データがないと InvalidOperationException(「シーケンスに要素が含まれていません」)になります。FirstOrDefault() は null を返すので、その後で null チェック(第4章)が必要です。障害調査でよく出会うポイントです。

async / await ─ 待ち時間のある処理

データベースへの問い合わせやファイルの読み書き、他システムとの通信は、結果が返るまで時間がかかります。その間プログラム全体を止めないようにする仕組みが async / await(非同期処理)です。

コード例 16-2 非同期メソッドを呼び出す
Console.WriteLine("受注データを取得します");
var orders = await OrderApi.GetOrdersAsync("山田商事");
Console.WriteLine($"{orders.Count}件取得しました");

static class OrderApi
{
    public static async Task<List<string>> GetOrdersAsync(string customer)
    {
        await Task.Delay(500);   // 通信など、時間がかかる処理の代わり(0.5秒待つ)
        return new List<string> { "A-001", "A-003" };
    }
}
実行結果
受注データを取得します
2件取得しました
  1. await:「終わるまで待って、結果を受け取る」。結果の List<string> が orders に入ります。
  2. async:「このメソッドの中で await を使う」という印。戻り値の Task<List<string>> は「いずれ List<string> を返す約束」という意味です。何も返さない場合は Task だけ(同期の void にあたる)です。
  3. メソッド名の末尾の Async は、「非同期メソッドです」という命名の慣習です。
async/await の読み方のコツ
  • async、await、Task<T>、～Async は、いったん無視して普通の処理として読めば、流れはほぼ理解できます。Task<Order> は「Order を返す」と読み替えましょう。
  • 古いコードの .Result や .Wait() は「非同期処理を無理やり待つ」書き方で、画面が固まる(デッドロック)原因になることがあります。

データベース連携 ─ SQL・ADO.NET・Entity Framework

基幹システムのデータは、ほぼ必ずデータベース(SQL Server、Oracle、PostgreSQL など)に保存されています。C#からデータベースを扱う方法は、主に3種類あります。

まず土台となる SQL の4つの基本命令を押さえておきましょう。

SQL意味例

Entity Framework Core(新しいシステムに多い) 
var orders = await _db.Orders
    .Where(o => o.CustomerId == customerId)
    .OrderBy(o => o.OrderDate)
    .ToListAsync();

データベース関連のコードを読むときのポイント
  • DbContext を継承したクラスの DbSet<Order> Orders が、テーブルとクラスの対応表です。
  • Entity Framework は、.NET Framework 用の Entity Framework 6 と、現在の .NET 用の Entity Framework Core(.NET と同様に最新は 10)があります。
  • SQL Server への接続部品は、新しい Microsoft.Data.SqlClient と古い System.Data.SqlClient があります(役割は同じ)。
  • 要注意:"… WHERE Name = '" + name + "'" のように入力値を文字列連結で SQL に埋め込むコードは、SQLインジェクション(不正な SQL を実行される攻撃)の危険があります。パラメーター(@name)を使うのが正しい書き方です。レビューでは必ず確認しましょう。
  • BeginTransaction / Commit / Rollback はトランザクション(複数の更新を「全部成功」か「全部取り消し」にする仕組み)です。

ログ出力

基幹システムでは、「いつ、誰が、何をして、何が起きたか」をログとして記録します。障害調査ではまずログを見るので、コードのどこでどんなログを出しているかを知っておくと役に立ちます。

_logger.LogInformation("受注を登録しました。受注番号:{OrderNo}", order.OrderNo);
_logger.LogWarning("在庫が少なくなっています。商品:{ProductCode} 残り:{Quantity}", code, qty);

ログレベル(重要度)用途

Warning問題になりそうな状況(処理は続行)
Error処理が失敗した

ログの {OrderNo} は $"" の埋め込みとは別物

LogInformation("…{OrderNo}", order.OrderNo) の {OrderNo} は、後ろに並べた値が順番に入る「穴」です(string.Format に近い)。文字列の先頭に $ は付きません。値が項目名付きで記録されるので、ログを検索・集計しやすくなります(構造化ログ)。

現在の .NET では ILogger(Microsoft.Extensions.Logging)が標準です。古いシステムでは log4net、NLog などのライブラリで log.Info("…")、logger.Error(ex, "…") のように書かれていることもあります。どこに出力されるか(ファイル、データベースなど)は設定ファイルで決まります。

依存性の注入(DI)─ 部品の組み立て表

新しい .NET のシステムでは、クラスが必要とする部品(データベース係、ログ係など)をコンストラクターの引数で受け取る書き方が標準です(第11章)。どのインターフェースにどのクラスを渡すかは、Program.cs に組み立て表として登録されています。

// Program.cs(組み立て表)
builder.Services.AddScoped<IOrderRepository, SqlOrderRepository>();
builder.Services.AddScoped<OrderService>();

// OrderService.cs(部品を受け取って使う側)
public class OrderService
{
    private readonly IOrderRepository _repository;
    private readonly ILogger<OrderService> _logger;

    public OrderService(IOrderRepository repository, ILogger<OrderService> logger)
    {
        _repository = repository;
        _logger = logger;
    }
}

public class ShippingService
{
    private readonly IOrderRepository _orders;
    private readonly ILogger<ShippingService> _logger;

    public ShippingService(IOrderRepository orders, ILogger<ShippingService> logger)
    {
        _orders = orders;
        _logger = logger;
    }

    public async Task<int> ShipTodayOrdersAsync(DateTime today)
    {
        var targets = (await _orders.GetUnshippedAsync())
            .Where(o => o.DueDate <= today)
            .OrderBy(o => o.DueDate)
            .ToList();

        foreach (var order in targets)
        {
            order.ShippedDate = today;
            await _orders.UpdateAsync(order);
            _logger.LogInformation("出荷済みにしました:{OrderNo}", order.OrderNo);
        }
        return targets.Count;
    }
}
答えと解説

「今日までに納期が来ている未出荷の受注を、納期の古い順に出荷済みにして、その件数を返す」処理です。

  • 3〜10行目:受注データの保管係(IOrderRepository)とログ係を、コンストラクターで受け取っています(DI)。実際の保管係のクラスは Program.cs を見れば分かります。
  • 12行目:Task<int> なので「いずれ int(件数)を返す」非同期メソッドです。
  • 14〜17行目:未出荷の受注を取得し(await)、納期が今日以前のものに絞り込み(Where)、納期順に並べ(OrderBy)、List にします。
  • 19〜24行目:1件ずつ出荷日を設定して更新し、ログに記録します。
  • 25行目:処理した件数を返します。

async、await、Task を読み飛ばしても、処理の流れはつかめることを確認してください。

この章のまとめ
  • x => 式 は「x について、式の結果」。LINQ は Where → OrderBy → Select → ToList の流れ作業。
  • await は「終わるのを待って結果を受け取る」。読むときは普通の呼び出しと同じと考えてよい。
  • DB アクセスは ADO.NET(SQL を直接)と Entity Framework(LINQ から SQL を生成)が中心。SQL の文字列連結は要注意。
  • ログは _logger.LogXxx(…)。設定は appsettings.json(新)/ App.config・Web.config(旧)。
  • インターフェースの中身は、Program.cs の DI の登録を見る。

総合演習 受注処理OrderProcessing.cs
using System;
using System.Collections.Generic;
using System.Linq;

namespace Company.Sales
{
    public interface IStockService
    {
        bool TryAllocate(string productCode, int quantity);
    }

    public class StockService : IStockService
    {
        private readonly Dictionary<string, int> _stocks = new()
        {
            ["P-100"] = 50,
            ["P-200"] = 5,
        };

        public bool TryAllocate(string productCode, int quantity)
        {
            if (!_stocks.TryGetValue(productCode, out int stock) || stock < quantity)
            {
                return false;
            }
            _stocks[productCode] = stock - quantity;
            return true;
        }
    }

    public record OrderLine(string ProductCode, int Quantity, decimal UnitPrice);

    public class OrderProcessor
    {
        private const decimal TaxRate = 0.10m;
        private readonly IStockService _stockService;

        public OrderProcessor(IStockService stockService)
        {
            _stockService = stockService;
        }

        public decimal Process(string orderNo, List<OrderLine> lines)
        {
            if (lines == null || lines.Count == 0)
            {
                throw new ArgumentException("明細がありません", nameof(lines));
            }

            foreach (var line in lines)
            {
                if (!_stockService.TryAllocate(line.ProductCode, line.Quantity))
                {
                    throw new InvalidOperationException(
                        $"{orderNo}:{line.ProductCode} の在庫が不足しています");
                }
            }

            decimal subtotal = lines.Sum(l => l.UnitPrice * l.Quantity);
            decimal tax = Math.Floor(subtotal * TaxRate);
            return subtotal + tax;
        }
    }

    public static class Program
    {
        public static void Main()
        {
            var processor = new OrderProcessor(new StockService());

            var orders = new Dictionary<string, List<OrderLine>>
            {
                ["A-001"] = new() { new("P-100", 10, 1200m), new("P-200", 2, 980m) },
                ["A-002"] = new() { new("P-200", 5, 980m) },
                ["A-003"] = new() { new("P-100", 3, 1200m) },
            };

            foreach (var (orderNo, lines) in orders)
            {
                try
                {
                    decimal total = processor.Process(orderNo, lines);
                    Console.WriteLine($"{orderNo}:受注確定 請求額 {total:N0}円");
                }
                catch (InvalidOperationException ex)
                {
                    Console.WriteLine($"エラー → {ex.Message}");
                }
            }
        }
    }
}
